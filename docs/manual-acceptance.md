# 阶段 8：接口与手动验收对照表

> 盘点日期：2026-09-08。依据当前 Controller、SecurityConfig、请求 DTO、相关 Service 和前端路由静态整理。共 8 个 Controller、34 个接口。本次没有发送业务请求，所有阶段 8 用例均为“待验收”，不将历史验收直接算成本轮通过。

## 使用方法与数据准备

- 后端基址 `http://localhost:8080`，前端 `http://localhost:5173`；实际运行地址变化时在本地工具中调整。
- 准备匿名身份、普通用户 A（卖家）、B（买家）、C（无关第三方）和管理员 M。身份变量与 Token 只保存在本地，不写入本文或集合导出。
- 使用专用测试分类、商品和用户，记录本轮创建的 ID；不要用已有真实交易测试付款、禁用、下架。验证码按当前开发方式本地取得，不保存到验收证据。
- 准备启用/停用分类，以及 A 发布的多件在售商品，分别用于取消、成交、下架场景。每个写入用例完成后检查相关查询结果与数据库状态；不只看成功提示。
- API 表的成功预期均为 HTTP 200、响应 `code=0`。失败用例同时记录 HTTP 状态、业务码、message，不将业务码当作 HTTP 状态。
- 每个受保护接口补测匿名请求（401）；每个管理员接口补测普通用户请求（403）。公开接口分别测试无 Token 和有效 Token；带 Token 时仍检查 Redis 黑名单，故障应为 503。
- 记录格式：`用例 ID / 角色 / 前置数据 ID / 请求（脱敏）/ 预期 / 实际 HTTP 与 code / 状态变化 / 证据位置 / 日期 / 通过或失败`。本文表格给出预期，执行后在文末结果表追加逐项结果。
