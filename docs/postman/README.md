# Postman 手动验收集合

导入文件：[校园二手交易平台.postman_collection.json](校园二手交易平台.postman_collection.json)。共 69 条请求：34 个接口模板、11 条流程辅助请求、24 条异常/权限请求。接口预期见每条请求的 Description，完整场景见 [手动验收对照表](../manual-acceptance.md)，失败语义见 [错误码表](../api/error-codes.md)。

## 导入与配置

1. 启动 MySQL、Redis 和后端；本地后端默认 `http://localhost:8080`。
2. 在 Postman 点击 **Import → Files**，选择集合 JSON。集合使用 Postman Collection v2.1 格式；导入后应看到 9 个文件夹、69 条请求。
3. 新建本地环境，按下表创建同名变量并选中该环境。集合内敏感值和数据 ID 均为空；环境同名变量覆盖集合占位值。凭据只填本地值，不共享、同步或带入导出文件。
4. 先执行登录请求，从响应 `data.token` 手动复制到对应环境变量。集合没有前置脚本、测试脚本或自动保存 Token 的脚本，也不输出 Token 到日志。
5. 从单条请求的 **Send** 开始，核对 HTTP 状态、JSON `code` 和数据状态，再继续下一步。不要把整个集合一次运行：其中包含下架、禁用、退出和互斥的订单状态场景。

| 变量 | 本地填写内容 |
| --- | --- |
| baseUrl | 默认 `http://localhost:8080`，不带末尾斜杠 |
| sellerUsername / sellerPassword / sellerEmail / sellerEmailCode | 卖家的本地测试凭据及注册验证码；不使用共享真实账户 |
| buyerUsername / buyerPassword / buyerEmail / buyerEmailCode | 另一个普通用户的凭据及验证码 |
| adminUsername / adminPassword | 已有本地管理员凭据；公开注册不能创建 ADMIN |
| sellerToken / buyerToken / adminToken | 各自登录响应的 `data.token`，只填 Token 本身，不带 `Bearer ` |
| thirdToken | 既非订单买家也非卖家的第三用户 Token；可复制登录模板、替换为第三用户本地凭据后取得 |
| categoryName / categoryId | 专用测试分类名；创建后将 `data.id` 填入 categoryId |
| disabledCategoryId | 另建并停用的专用分类 ID，不随意停用已有业务分类 |
| productId / orderId | 成交分支专用商品 ID 与订单 ID |
| cancelProductId / cancelOrderId | 取消分支专用商品 ID 与订单 ID，与成交分支分开 |
| targetUserId | 用于禁用/启用验收的专用用户 ID；禁用买家场景必须指向该买家 |
| missingId | 已确认不存在的正整数 ID；按商品/订单场景分别确认 |
| page / pageSize | 默认 1 / 12；非法分页请使用异常模板或手动替换 |
| imageBase64 | 可选本地图片素材备用变量；发布模板默认空图片，要测合法图片时手动替换 body 的 imageBase64 值 |

JSON 中 ID 占位符不带引号，例如 `"productId": {{productId}}`。先填数字 ID 再发送；空变量会形成非法 JSON。密码/邮箱等字符串变量若包含双引号或反斜杠，要检查最终请求体的 JSON 转义，避免把模板替换失败误记为业务失败。

## 推荐执行顺序

### 1. 准备身份与分类

- 新用户：执行 A01 发送验证码、A02 注册卖家；买家使用“08 流程辅助”的验证码和注册请求。验证码按 [本地取码说明](../logging.md) 从 Redis 复制到剪贴板，不再从后端日志获取，不附到验收记录。
- 已有专用用户可跳过注册准备，但注册功能本身仍需另行验收。
- 执行 A03 卖家登录、辅助文件夹的买家登录和管理员登录，分别填写 Token。
- 执行 A04、H01、M06，验证当前用户、已登录健康检查和管理员权限。
- 执行 C03 创建专用分类，保存 categoryId；再执行 C01/C02 确认公开和管理员列表。**C05 模板为停用，先不要执行。**

### 2. 成交分支

1. A 使用 P04 发布专用商品，将响应 `data.id` 填入 productId。
2. 执行 P01/P02/P03/P05；需要编辑时先执行 P06，保持商品 ON_SALE。
3. B 执行 F01/F03；重复收藏应仍成功且关系只有一条。取消收藏用 F02，重复取消仍成功。
4. 在商品仍在售时执行越权编辑、自己购买等异常请求；不要执行 P07/M04 下架这个商品。
5. B 执行 O01，下单后保存 `data.id` 为 orderId；核对订单 PENDING_PAYMENT、商品 LOCKED。
6. 执行 O02/O03/O04 和辅助的卖家查订单；此时可测试第三方查看、卖家付款、未付款确认完成等拒绝场景。
7. B 执行 O06，核对订单 PAID、商品 SOLD；再执行 O07，核对 COMPLETED/SOLD。重复付款或重复完成应失败，不能改变状态。

### 3. 取消分支

1. 使用辅助“发布取消分支专用商品”，保存 cancelProductId。
2. 使用辅助“取消分支下单”，保存 cancelOrderId。
3. 使用辅助“取消分支取消”和“取消分支查订单”，核对 CANCELLED/ON_SALE。
4. 使用异常文件夹的重复取消、已取消订单付款，预期 HTTP 400/code=4002。

正常模板 O05 引用 orderId；取消分支推荐使用辅助请求，避免误取消成交分支。

### 4. 管理、异常与退出

- 用另外的专用在售商品测试 P07 和 M04；若复用 productId，先记录成交分支 ID，测试后恢复本地变量。
- C04/C05 测试分类修改、停用，随后使用辅助请求恢复启用。停用分类发布请求需先设置 disabledCategoryId。
- M01–M05 测试管理员查询/操作，普通用户访问管理接口应被拒绝。用户禁用结束后用辅助请求恢复启用。
- 在完成卖家操作后执行 A05，保留原 sellerToken 再查个人信息，预期 401；后续操作需要重新登录。
- 重复用户名/邮箱注册：重新取得有效验证码后修改注册模板再发送，否则可能先命中验证码错误。重复分类名、非法图片、错误 JSON 等已有独立模板。
- 其余分页接口、枚举筛选、字段边界、并发抢购和数据库回滚按对照表逐项扩展请求；69 条模板不等于所有分支都已覆盖或已通过。

## Redis 验收与取证

集合不会自动暂停 Redis 或更改权限。使用 P03/C01 重复请求，并在终端观察缓存 TTL 与后端命中日志；业务写入后检查对应键失效及再次回填。

无响应、连接拒绝、黑名单仅写入失败，需要先建立独立故障环境，再选用 A04/A05/A01 与匿名 C01/P03。不同实例可临时覆盖 baseUrl。匿名降级成功、有 Token 认证故障 503、退出失败不误报成功，恢复后重试成功且旧 Token 401。步骤与历史证据见 [阶段 7 故障记录](../学习清单/阶段-7-Redis故障验收-2026-09-08.md)。

按对照表记录请求名称、身份、前置 ID、实际 HTTP/code、业务状态前后值、日期和结论；截图/响应证据去除密码、Token、验证码和完整图片。数据库核对使用只读查询；专用数据需要清理或恢复时记录具体操作，不清空业务库。
