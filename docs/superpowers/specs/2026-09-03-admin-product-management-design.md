# 阶段 6：管理员商品管理设计

## 目标

管理员能够跨卖家分页查看和筛选商品，并且只能下架当前为 `ON_SALE` 的商品；商品处于 `LOCKED`、`SOLD` 或 `OFF_SHELF` 时不显示下架入口。学生没有商品管理菜单，直接访问路由跳转 `/403`。

## 前端数据边界

前端 API 模块使用 `GET /api/admin/products` 传递分页、卖家 ID、分类 ID、状态与关键词；使用 `PATCH /api/admin/products/{id}/off-shelf` 下架。状态为 `ProductStatus` 字符串枚举，筛选 ID 仅发送正整数，空字符串和未选条件不发送。后端是状态与权限的最终保障，前端仅负责减少误操作。

## 页面与交互

`ProductManageView.vue` 沿用用户管理页的米白、墨绿、表格化管理员控制台风格：标题区显示 `ADMIN CONSOLE`、页面说明和总商品数；筛选区包含关键词、卖家 ID、分类 ID、状态、查询与重置；表格显示缩略图/占位、商品标题与价格、卖家、分类、状态、发布时间和操作。

商品状态标签使用明确语义：`ON_SALE` 为成功色，`LOCKED` 为警告色，`SOLD` 与 `OFF_SHELF` 为中性色。仅 `ON_SALE` 显示“下架”按钮；确认框说明商品下架后不能重新上架，且不会影响已存在的订单。操作完成或出现状态冲突时重新加载当前页。页面提供 skeleton、错误重试、空状态、分页；窄屏时筛选区换行，表格可横向滚动。

## 路由与菜单

新增 `/admin/products` 路由，设定 `requiresAuth: true` 与 `roles: ["ADMIN"]`。管理员侧栏的管理区域新增“商品管理”，与“分类管理”“用户管理”并列；学生不渲染整个管理区域。

## 验收

1. 管理员可加载、筛选、重置和翻页，且全部筛选参数与分页参数正确传递。
2. 仅在售商品可打开下架确认并成功刷新；锁定、已售、已下架商品没有下架按钮。
3. 操作失败时显示后端错误并刷新当前页，避免前端保留过期状态。
4. 学生无管理菜单，直接访问 `/admin/products` 跳转 `/403`。
5. 按用户决定，不运行构建、格式化或自动测试，以浏览器手动验收。
