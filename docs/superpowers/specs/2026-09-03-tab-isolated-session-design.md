# 标签页隔离登录会话设计

## 目标

允许同一浏览器的不同普通标签页同时登录不同账号，例如管理员页与学生页并行验收；不再要求使用无痕窗口、不同浏览器或 Profile。

## 方案

前端认证状态从 `localStorage` 改存至 `sessionStorage`：

- Token 键名继续为 `campus-trade-token`，用户信息键名继续为 `campus-trade-user`。
- 每个标签页读取、写入和清除自己的会话数据；一个标签页登录、退出或收到 401，不影响其他标签页。
- 同一标签页刷新后，`sessionStorage` 仍存在，登录保持有效。
- 新开或关闭后重开的标签页没有会话，需单独登录；这是隔离不同账号的必要边界。

后端 JWT、请求拦截器、路由守卫和 API 契约均不变。`AuthStore` 仍是唯一的前端认证状态入口，只替换底层存储对象，避免散落的存储访问。

## 验收

1. 标签页 A 登录管理员后，刷新 A 仍保持管理员会话。
2. 标签页 B 打开同一站点时显示未登录，可独立登录普通学生账号。
3. A 的管理员菜单和 `/admin/users` 可用；B 没有管理员菜单且直接访问管理员路由跳转 `/403`。
4. B 退出或因 401 清除会话后，A 仍保持管理员登录状态；反向场景同理。
5. 不运行构建、格式化或自动测试；以浏览器手动验收。
