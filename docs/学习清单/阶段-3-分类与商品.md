# 阶段 3：商品分类与商品

## 目标

完成分类和商品的完整 CRUD、商品广场、搜索、筛选、分页、图片 Base64 上传与“我的发布”。

## 1. 表结构与状态

- [ ] 先写 `docs/api/phase-3.md`：所有接口、字段、角色、商品状态和编辑限制。
- [ ] 创建 `category` 表：`id`、`name`（唯一）、`sort`、`status`、创建/更新时间；状态 `ENABLED`、`DISABLED`。
- [ ] 创建 `product` 表：`id`、`seller_id`、`category_id`、`title`、`description`、`price`、`image_base64`（LONGTEXT）、`status`、`view_count`、创建/更新时间。
- [ ] 商品状态统一为：`ON_SALE` 在售、`LOCKED` 已锁定、`SOLD` 已售出、`OFF_SHELF` 已下架。
- [ ] 给商品增加 `(status, created_at)`、`category_id`、`seller_id` 索引；用迁移插入至少 5 个启用分类。

## 2. 后端分类

- [ ] 公共接口：`GET /api/categories`，只返回启用分类，按 `sort` 排序。
- [ ] 管理员接口：分类新增、修改名称/排序、启用/停用、查看所有分类；管理页面放到阶段 6。
- [ ] 分类名去空格后不能为空，长度 1–30，且不可重复。
- [ ] 发布商品时分类不存在或被停用，都必须拒绝。

## 3. 后端商品

- [ ] 接口：商品分页列表、详情、发布、修改、下架、我的发布列表。
- [ ] 列表参数：`page`、`pageSize`、可选 `categoryId`、可选关键词；最大每页 50 条；关键词只通过参数化 SQL 搜标题和描述。
- [ ] 参数校验：标题 2–60，描述 10–2000，价格大于 0 且最多两位小数。
- [ ] 图片只允许一张 Data URL Base64；后端解码后再次判断，类型只能 JPEG/PNG/WebP，原始大小最大 2 MB，不能只相信前端 MIME 声明。
- [ ] 发布时卖家 ID 必须取当前登录用户，状态必须由后端设为 `ON_SALE`；前端不能传卖家 ID 或状态。
- [ ] 仅卖家本人且商品处于 `ON_SALE` 时能修改；仅卖家本人且在售时能主动下架。
- [ ] 本阶段不能下架 `LOCKED` 商品，避免破坏待付款订单；管理员强制下架放阶段 6。
- [ ] 查看公开详情时增加浏览量；学习项目可以接受浏览量近似值。

## 4. 后端测试

- [ ] 测试分页、搜索、分类筛选组合。
- [ ] 测试卖家发布并编辑自己的在售商品。
- [ ] 测试其他用户修改/下架返回 403。
- [ ] 测试无效分类、价格、图片格式、图片大小、状态。
- [ ] 测试下架商品不出现在公开列表，详情浏览量正确增加。

## 5. Vue 页面

- [ ] 建立分类和商品 API 模块。
- [ ] 商品广场：分类筛选、关键词搜索、重置、分页卡片、价格、分类、卖家名、图片占位、加载/空/错误状态。
- [ ] 商品详情：展示完整信息与卖家；收藏、下单功能后续再加。
- [ ] 发布/编辑表单：从后端加载分类；前端也检查图片类型/大小后转 Base64，显示预览；提交中有加载和失败提示。
- [ ] 我的发布：分页展示、编辑和下架按钮，按钮必须依据商品状态显示。
- [ ] 菜单接入商品广场、发布商品、我的发布；后两者必须登录。
- [ ] 测试、构建、手动发布一件商品并从另一账号浏览后提交 Git。
