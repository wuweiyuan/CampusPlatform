# 阶段 5：订单状态机与事务

## 目标

实现单件商品交易：下单、取消、模拟付款、确认完成。核心是状态机和事务，确保同一商品只有一个买家成功下单。

## 1. 先固定状态表

| 操作 | 谁能操作 | 订单当前状态 | 商品当前状态 | 订单结果 | 商品结果 |
|---|---|---|---|---|---|
| 创建订单 | 买家 | 无 | `ON_SALE` | `PENDING_PAYMENT` | `LOCKED` |
| 取消订单 | 买家 | `PENDING_PAYMENT` | `LOCKED` | `CANCELLED` | `ON_SALE` |
| 模拟付款 | 买家 | `PENDING_PAYMENT` | `LOCKED` | `PAID` | `SOLD` |
| 确认完成 | 买家 | `PAID` | `SOLD` | `COMPLETED` | `SOLD` |

- [ ] 把此表、接口、权限写到 `docs/api/phase-5.md`。
- [ ] 明确：用户不能买自己的商品；卖家不能代替买家取消/付款/完成；前端不得传价格、卖家、状态、时间。

## 2. 订单表

- [ ] 创建 `orders` 表：`id`、唯一 `order_no`、`buyer_id`、`seller_id`、`product_id`、`amount`、`status`、`created_at`、`paid_at`、`completed_at`、`updated_at`。
- [ ] 对买家订单、卖家订单、商品 ID、订单状态、订单号建立索引。
- [ ] 订单号只能由后端生成，格式写入文档，数据库唯一约束兜底。

## 3. 后端事务

- [ ] 接口：创建订单、订单详情、我的买入订单、我的卖出订单、取消、模拟付款、确认完成。
- [ ] 先写并发测试：两个不同买家同时购买同一在售商品，只有一个成功，商品最终为 `LOCKED`。
- [ ] 创建订单必须 `@Transactional`：查询/原子更新商品仅允许 `ON_SALE → LOCKED`，检查不能买自己，插入订单快照（当前价格、卖家）。条件更新没有更新到行时表示已被别人抢走，返回业务错误。
- [ ] 取消也必须事务：确认调用者是买家，订单只能 `PENDING_PAYMENT → CANCELLED`，商品 `LOCKED → ON_SALE`。
- [ ] 付款也必须事务：确认买家，订单只能 `PENDING_PAYMENT → PAID`，记录 `paid_at`，商品 `LOCKED → SOLD`。
- [ ] 完成也必须事务：确认买家，订单只能 `PAID → COMPLETED`，记录 `completed_at`，商品仍是 `SOLD`。
- [ ] 每次变更都从数据库读取当前状态；重复支付、越级完成、重复取消都必须报错，不能静默成功。

## 4. 测试

- [ ] 正常：下单→取消，商品回到在售。
- [ ] 正常：下单→付款→完成，商品为已售。
- [ ] 不能购买自己、不能购买下架/锁定/已售商品。
- [ ] 其他用户不能取消/付款/完成。
- [ ] 顺序错误均失败；并发下单只有一个成功。
- [ ] 买入和卖出订单列表只返回当前用户相关数据，且分页正确。
