# 阶段 7：Redis 故障验收（2026-09-08）

> 最新结果：超时与 401 问题已修复，8080 服务通过 Redis 无响应回归；同日使用独立临时实例补验连接拒绝及黑名单读取成功、写入失败，两项均通过。早期失败数据保留为修复前证据。

## 最后两项补验

使用相同代码启动临时后端 8081，连接独立 Redis 6389（不持久化），不停止用户的 6379 Redis。首次临时 Redis 因 locale 配置启动失败，该轮不计完整验收；改用 `LC_ALL=C` 并确认正常基线后重跑。

1. **真实连接拒绝**：先确认 `/api/auth/me`、分类、热门均返回 200，再停止临时 Redis。分类与热门约 2.057 秒返回 200（6 条、10 条）；个人信息、退出、验证码约 1.021–1.023 秒返回 503。日志确认连接拒绝及降级路径。重启临时 Redis 后原 Token 的个人信息返回 200。
2. **黑名单读取成功、写入失败**：对临时 Redis 执行 `ACL SETUSER default -set`，保留 EXISTS 等读取权限。个人信息返回 200，证明黑名单读取可用；退出约 0.023 秒返回 503，服务日志记录 `RedisSystemException`，没有误报退出成功。此时原 Token 仍返回 200，符合退出失败未撤销的状态。恢复 `+set` 后重试退出返回 200，原 Token 再访问个人信息返回 401。

临时 Redis 和后端已关闭，原有 Redis `PING` 返回 `PONG`，8080 分类接口返回 200。本轮未改业务代码，未运行自动测试、前端构建或格式化。

剩余文档收尾事项：明确开发模式验证码日志与阶段日志边界的口径，并汇总此前已验收的缓存命中、未命中、失效证据；本次没有重新演示全部业务写操作。

## 修复及最终回归

- `application.yml` 设置 Redis `connect-timeout: 1s`、`timeout: 1s`。
- JWT 过滤器处理 Redis 连接、系统和查询超时异常，清除本次认证上下文并直接返回 HTTP 503，不继续放行请求。
- 全局异常处理为控制器中的 Redis 连接、系统及查询超时异常返回 HTTP 503；错误信息不包含异常细节。`QueryTimeoutException` 也可能来自数据库，因此全局提示使用通用服务不可用文案。
- 后端离线编译 `mvn -o -DskipTests compile` 成功，未运行自动测试、前端构建或格式化。
- 临时 8081 实例实测：匿名分类和热门约 2.05 秒返回 HTTP 200；认证相关故障约 1 秒返回 HTTP 503；日志确认缓存读写失败、MySQL 降级及认证拒绝。无效 Token 返回 401，正常退出成功后原 Token 返回 401。临时实例已关闭。
- 用户重启 8080 后，再次执行 Redis `CLIENT PAUSE 8000 ALL`：匿名分类和热门约 2.04 秒返回 HTTP 200（6 条、10 条）；个人信息、退出、带 Token 的分类及验证码约 1.01–1.03 秒返回 HTTP 503。
- Redis 自动恢复后 `PING` 为 `PONG`，分类、热门和原 Token 的个人信息接口均约 0.01 秒返回 HTTP 200。

带 Token 的公开请求仍执行黑名单检查，Redis 故障时返回 503；匿名公开请求才能降级查询。这保留了认证失败不放行的边界。

## 结论

故障验收未完全通过。匿名分类和热门查询能够降级返回数据，但延迟超过前端超时；认证相关故障被返回为 401，未明确区分服务故障与无效 Token。

## 实测方法与结果

对本机 Redis 执行 `CLIENT PAUSE 150000 ALL`，模拟 Redis 无响应；不是浏览器请求拦截，也不是 Redis 停机/连接拒绝测试。通过真实 HTTP 请求并发验证，Token 仅在内存使用，未记录密码或完整 Token。

| 请求 | Redis 正常 | Redis 无响应 |
| --- | --- | --- |
| 匿名 `GET /api/categories` | HTTP 200，6 条 | 约 120.09 秒后 HTTP 200，code=0，6 条 |
| 匿名 `GET /api/products/hot` | HTTP 200，10 条 | 约 120.09 秒后 HTTP 200，code=0，10 条 |
| 有效 Token `GET /api/auth/me` | HTTP 200 | 约 60.04 秒后 HTTP 401 |
| 有效 Token `POST /api/auth/logout` | 本次未测正常退出 | 约 60.04 秒后 HTTP 401 |
| 有效 Token `GET /api/categories` | 本次未单独记录正常基线 | 约 60.04 秒后 HTTP 401 |
| 匿名 `POST /api/auth/email-code` | 本次未测正常发送 | 约 60.05 秒后 HTTP 401 |

上述 401 响应一致为 `{"code":401,"message":"未登录或 Token 无效","data":null}`。未出现故障时认证静默放行，但服务错误提示不符合要求。退出请求在黑名单读取阶段就失败，未独立覆盖黑名单写入失败。

浏览器中调用项目实际 Axios 实例请求热门接口，10 秒后返回 `ECONNABORTED / timeout of 10000ms exceeded`。因此后端最终返回成功不能代表页面降级可用。

## 代码核对

- 分类与热门服务都在缓存读取异常后查询 MySQL，再尝试写缓存；两次 Redis 等待与实测约 120 秒一致。前端 `src/api/http.ts` 超时为 10 秒。
- `JwtAuthenticationFilter` 未处理 Redis 异常；`GlobalExceptionHandler` 未提供 Redis 故障响应，安全配置也未明确放行错误分派。需处理故障响应，避免最终误报 401；具体异常栈尚未从运行日志核验。
- 分类和热门缓存代码有降级 warning。本次后端标准输出连接 IDE 管道，未取得实时日志，不能勾选日志验收完成。
- `EmailCodeService` 仍在开发邮件模式输出验证码。`docs/cache.md` 已注明这一开发约定，但它与交接记录的“不记录验证码”要求存在口径差异，需明确阶段验收范围。

## 恢复确认

主动 `CLIENT UNPAUSE` 命令等待 10 秒后超时；Redis 随后按 150 秒期限自动恢复。恢复后实测 `PING` 为 `PONG`，匿名分类返回 6 条、热门返回 10 条，普通用户登录及 `/api/auth/me` 正常。分类与热门恢复后请求分别约 0.023 秒和 0.006 秒。

未删除 Redis 数据，未修改业务代码或配置，未运行构建、格式化或自动测试。故障验证码请求使用专用测试邮箱，暂停期间排队的限频写入可能在恢复后执行，并按原 60 秒 TTL 过期。
