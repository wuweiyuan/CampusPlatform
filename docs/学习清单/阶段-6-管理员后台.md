# 阶段 6：管理员后台

## 目标

仍在同一个 Vue 项目中，为管理员提供分类、用户、商品、订单管理；所有管理员接口必须由后端再校验角色。

## 本阶段文件地图

不要重新创建第二个前端项目。后端在现有模块中新增 `admin` 相关 Controller/Service，或在各模块内增加管理员接口，推荐统一放：

```text
admin/controller/AdminCategoryController.java
admin/controller/AdminUserController.java
admin/controller/AdminProductController.java
admin/controller/AdminOrderController.java
admin/service/AdminCategoryService.java
admin/service/AdminUserService.java
admin/service/AdminProductService.java
admin/service/AdminOrderService.java
```

它们仍复用 `category`、`product`、`order` 的 Entity/Mapper，不能再创建重复的表或重复 Entity。前端新建目录 `campus-trade-web/src/views/admin/`，文件为 `CategoryManageView.vue`、`UserManageView.vue`、`ProductManageView.vue`、`OrderManageView.vue`；在 `src/router/index.js` 和 `src/layouts/AppLayout.vue` 中追加管理员路由和菜单。

## 清单

- [ ] 在 Postman 中用普通 `USER` Token 访问每一个 `/api/admin/**` 接口，确认都返回 HTTP 403。
- [ ] 在安全配置或统一注解中集中处理 ADMIN 权限，不要在每个 Controller 随意复制判断。
- [ ] 创建/记录一个本地管理员账号，密码使用 BCrypt；公开注册永远只创建 `USER`。
- [ ] Vue 的 `/admin` 路由标记为 `requiresAuth: true`、`roles: ['ADMIN']`；普通用户直接访问跳 403。

### 分类管理

- [ ] 接口：查看所有分类（含停用）、新增、修改名称/排序、启用/停用。
- [ ] 分类停用后，已经打开的发布商品表单提交也必须被后端拒绝。
- [ ] 页面：分类表格、表单/弹窗、排序、启用状态、加载/空/错误状态。

### 用户管理

- [ ] 接口：按用户名/邮箱/角色/状态分页查用户；绝不返回密码哈希、JWT 内容等敏感字段。
- [ ] 接口：启用/禁用用户；不能禁用当前登录管理员。
- [ ] 选择并记录规则：推荐每次 JWT 请求都检查用户状态，用户被禁用后即使旧 Token 也失效。
- [ ] 页面：用户表格、筛选、状态标签、启用/禁用确认。

### 商品与订单管理

- [ ] 接口：管理员商品分页，支持卖家/分类/状态/关键词筛选。
- [ ] 管理员仅能下架 `ON_SALE` 商品；`LOCKED` 商品有买家待付款，阶段 6 不强制下架。
- [ ] 接口：管理员订单分页，支持订单号/状态/买家/卖家筛选；本阶段只读，管理员不能替用户付款、取消或完成订单。
- [ ] 页面：商品管理表、订单管理表，支持状态显示、详情跳转、加载/空/错误状态。

### 验收

- [ ] 用学生和管理员两种 Token 测每个管理接口。
- [ ] 用 Postman 手动验证禁用用户不能登录；若实现每请求查状态，也验证旧 Token 失效。
- [ ] 用 Postman 手动验证管理员不能下架锁定商品，不能变更用户订单状态。
- [ ] 分别以学生/管理员登录浏览器，检查菜单、直接输入 URL、接口返回都正确。
- [ ] 在浏览器以学生/管理员身份各操作一次；运行 `npm run build` 后提交 Git。
