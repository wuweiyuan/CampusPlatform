## 本阶段边界

本阶段只实现一件商品对应一次正在进行的交易，不做购物车、库存数量、议价、退款、超时自动取消、物流、消息通知或真实支付。

- 买家不能购买自己发布的商品。
- 价格、卖家、商品状态、订单状态和时间一律由后端从数据库决定；前端请求只提交 `productId`。
- 买家之外的用户（包括卖家）不能取消、付款或确认该订单。
- 重复取消、重复付款、越级确认和状态冲突都必须失败，不能做成幂等成功。
- 所有状态改变必须在 `@Transactional` 方法中完成；任意一步失败都要回滚订单和商品状态。

## 固定状态机

| 操作 | 操作者 | 订单状态变化 | 商品状态变化 |
| --- | --- | --- | --- |
| 创建订单 | 买家 | 无 → `PENDING_PAYMENT` | `ON_SALE` → `LOCKED` |
| 取消订单 | 该订单买家 | `PENDING_PAYMENT` → `CANCELLED` | `LOCKED` → `ON_SALE` |
| 模拟付款 | 该订单买家 | `PENDING_PAYMENT` → `PAID` | `LOCKED` → `SOLD` |
| 确认完成 | 该订单买家 | `PAID` → `COMPLETED` | 保持 `SOLD` |

`order/enums/OrderStatus.java` 已完成，包含 `PENDING_PAYMENT`、`CANCELLED`、`PAID`、`COMPLETED`，避免在 Service 中散落字符串。

### 事务的关键顺序

1. `createOrder` 标注 `@Transactional`。读取商品并检查存在、买家不是卖家；随后执行条件更新 `UPDATE product ... WHERE id = ? AND status = 'ON_SALE'`。更新行数不是 `1` 就说明已被抢购或不可交易，返回业务错误。
2. 商品锁定成功后，从数据库取得卖家和价格，生成订单号并插入订单快照，初始状态为 `PENDING_PAYMENT`。插入失败必须使商品锁定回滚。
3. 取消、付款、确认完成均先读取当前订单，先判断调用者是否为买家，再做“订单 ID + 预期状态”的条件更新；受影响行数不是 `1` 即为状态冲突。
4. 取消和付款还要在同一事务中对关联商品执行对应的条件更新：`LOCKED → ON_SALE` 或 `LOCKED → SOLD`。任一更新失败即抛异常并整体回滚。
5. 确认完成仅在 `PAID` 时更新订单并写入 `completed_at`，商品保持 `SOLD`。
