# 阶段 8：手动验收、质量与文档

## 目标

在部署前让项目可以用 Postman 和浏览器手动验收、可复现、可说明，而不是“只在自己电脑能跑”。

## 本阶段文件地图

本阶段不新建 `src/test` 或 `.spec.js` 测试文件。文档集中更新 `README.md`、`docs/api/`、`docs/cache.md`、`.env.example`；Postman 集合导出到 `docs/postman/校园二手交易平台.postman_collection.json`，不要导出真实 Token、密码或邮箱验证码。

## 清单

### Postman 后端验收

- [ ] 导出一份不包含 Token/密码/验证码的 Postman 集合，并在 README 写导入方法。
- [ ] 用 Postman 覆盖：邮箱注册、JWT 退出、商品归属、分类状态、收藏唯一性、订单全部状态、管理员权限、Redis 失效。
- [ ] 用 Postman 覆盖异常：页码/大小非法、不存在 ID、参数校验、Base64 非法、用户禁用、唯一键重复。
- [ ] 重点手动验证订单事务：让一个商品下单成功，再看商品状态、订单记录是否同时正确；取消后两项是否同时恢复。记录每次请求和预期结果。

### API、错误和日志

- [ ] 所有接口在 `docs/api/` 中有请求/响应示例。
- [ ] 建立错误码表：错误码、HTTP 状态、用户可见信息、触发条件。
- [ ] 参数错误要能指出字段，但不返回堆栈给前端。
- [ ] 增加请求 ID 或统一日志上下文；可记录用户 ID 与操作类型，绝不记录密码、验证码、JWT、SMTP 授权码、完整 Base64 图片。

### 前端

- [ ] 每个数据页检查四种状态：加载中、有数据、空数据、请求失败。
- [ ] 在浏览器手动验证认证拦截、商品搜索分页、收藏变更、订单按钮状态。
- [ ] 使用项目声明的 Node 版本运行 `npm run build`。
- [ ] 检查窄屏：登录、注册、商品卡、商品表单、订单列表、管理员表格；记录暂不支持的范围。

### 文档与总验收

- [ ] README 包含：项目简介、架构图、环境要求、变量、迁移、启动、Postman 手动验收、构建、演示账号、主流程。
- [ ] 提交 `.env.example`，只有变量名和安全示例值。
- [ ] 写手工验收脚本：用户注册→登录→发布；第二用户收藏→下单→付款→完成；管理员管理；每一步写预期状态。
- [ ] 检查 Git：不可提交 `.env`、密钥、数据库备份、`node_modules`、`target`、IDE 文件。
- [ ] 从 README、Postman 集合和浏览器重新走一遍完整流程；通过后提交 Git。
