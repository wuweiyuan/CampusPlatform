# 阶段 6：交接记录（2026-09-01）

> 目标：在同一个 Vue 项目中提供管理员分类、用户、商品和订单管理。所有管理员能力必须由后端验证 `ADMIN` 角色；前端菜单和路由守卫只负责体验，不能替代后端权限控制。

## 当前结论：下一步做什么

阶段 6 范围较大，按以下四个小节依序完成，避免把权限、数据与页面一次性混在一起：

1. **管理员身份与统一权限保护**：准备本地管理员账号；集中限制 `/api/admin/**` 为 `ADMIN`；确认普通 `USER` Token 一律返回 `403`。
2. **分类管理**：管理员查看全部分类（含停用）、新增、编辑名称/排序、启用/停用；已停用分类必须使商品发布/编辑在后端失败。
3. **用户管理**：分页筛选、启用/禁用；禁止管理员禁用自己；每次 JWT 请求检查用户状态，使禁用用户的旧 Token 立即失效。
4. **商品、订单与前端管理台**：管理员商品筛选与仅对在售商品下架；订单只读筛选；接入四个管理页面、动态菜单与路由守卫。

“管理员身份与统一权限保护”已完成：已有本地管理员账号；管理员 Token 请求 `/api/admin/categories` 返回 200，普通 `USER` Token 返回 403。分类管理接口及“停用分类后拒绝商品提交”也已完成 Postman 验收；下一步接分类管理页面。

阶段 6 原始需求见：[阶段-6-管理员后台.md](阶段-6-管理员后台.md)。

## 开始前的项目状态

- 后端：`campus-trade-server`，根包为 `com.campus.trade.campustradeserver`；阶段 6 推荐新建 `admin/controller` 与 `admin/service`，复用已有分类、用户、商品、订单的 Entity/Mapper，不新建重复表。
- 前端：`campus-trade-web`，Vue 3 + TypeScript；已有路由守卫，会读取 `meta.requiresAuth` 和 `meta.roles`，管理员路由可沿用 `roles: ["ADMIN"]`。
- 认证：JWT 中已有用户身份与角色；公开注册只能创建 `USER`，本地管理员账号必须单独创建，密码保持 BCrypt 哈希。
- 阶段 5：订单后端、分页接口与前端交易闭环已实现；交接记录已更新。工作区仍有阶段 5 的未提交改动，开始阶段 6 时必须保留，不能覆盖或混入无关修改。
- 当前用户决定：不主动运行前端构建、格式化或自动测试；后端与前端以 Postman、Apifox、浏览器进行手动验收，并在最终记录中如实说明未执行的命令。

## 阶段边界

- 管理员可以管理分类、用户、商品和查看订单，但本阶段不新增第二个前端项目，也不新增第二套用户、商品、订单表。
- 管理员订单接口只读：不能替用户付款、取消或确认完成订单。
- 管理员只能下架 `ON_SALE` 商品；`LOCKED` 商品有待付款买家，本阶段不强制下架。
- 用户列表绝不返回密码哈希、JWT 或其他敏感认证数据。
- 管理员不能禁用当前登录的管理员账号。
- 用户被禁用后，推荐每次 JWT 请求读取用户状态并拒绝该请求；这样旧 Token 立即失效。

## 每小节的固定验收

1. 先在 `docs/api/` 写清接口、参数、响应、权限和错误情况。
2. 先用普通 `USER` Token 请求每一个 `/api/admin/**`，预期 HTTP 403。
3. 再用管理员 Token 验证正常、参数错误、越权与状态冲突场景。
4. 后端通过后接 Vue 页面；浏览器分别使用学生和管理员身份检查菜单、直接访问 URL 和接口行为。
5. 每小节完成后补回本文件的结果，再开始下一小节。
