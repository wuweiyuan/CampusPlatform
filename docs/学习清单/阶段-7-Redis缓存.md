# 阶段 7：Redis 缓存与失效

## 目标

让 Redis 的使用可观察、可解释：邮箱验证码、退出黑名单、分类缓存、热门商品缓存。

## 清单

- [ ] 创建 `docs/cache.md`，为每个键记录：键名、值结构、TTL、谁写、谁读、何时删除。
- [ ] 分类缓存键 `category:list`：启用分类、按排序展示、TTL 30 分钟。
- [ ] 热门商品键 `product:hot`：状态 `ON_SALE` 的前 10 条，按 `view_count DESC, created_at DESC`，TTL 10 分钟。
- [ ] 保留验证码、发送限频、JWT 黑名单键及其阶段 1 过期策略。
- [ ] 缓存值建议使用专用 DTO 的 JSON，不要直接缓存带敏感/隐藏字段的 Entity。

### 分类缓存

- [ ] 测试第一次查分类：查 MySQL 并写 `category:list`；第二次查：命中 Redis。
- [ ] 实现 Cache Aside：先查 Redis，未命中再查 MySQL 后回填。
- [ ] 分类新增、修改、排序、启用、停用成功后删除 `category:list`；事务失败时不要当成成功删除。
- [ ] 测试删除缓存后的下一次请求能查到新数据。

### 热门商品缓存

- [ ] 写专用 SQL 查询前 10 条热门在售商品。
- [ ] 测试：未命中→查库→写 Redis→命中。
- [ ] 商品发布/修改/下架、订单创建/取消/付款、浏览量更新后，都删除 `product:hot`。学习阶段只删不重建即可。
- [ ] 提供 `GET /api/products/hot`，并在商品广场展示热门区域。

### 稳定性与观察

- [ ] 日志记录缓存命中、未命中、写入、删除；绝不记录验证码、密码、完整 JWT、Base64 图片。
- [ ] Redis 不可用策略：验证码、登录退出相关功能给出明确服务错误；分类/热门读取可降级查 MySQL 并记录警告；商品和订单事务仍以 MySQL 为准，缓存删除在事务成功后尽力执行。
- [ ] 用日志或 `redis-cli` 演示缓存未命中和命中；测试缓存失效。
- [ ] 测试、构建、文档与 Git 提交完成。
