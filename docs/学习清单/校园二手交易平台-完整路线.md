# 校园二手交易平台：完整自学路线

> 你亲自写代码；每完成一个阶段，再开始下一个阶段。每一阶段都需要：接口自测、前端联调、记录问题、Git 提交。

## 你的学习规则（之后我必须遵守）

你是从零开始做项目，不需要预先知道 Controller、Service、异常处理、DTO 或测试怎么写。以后每次我让你做一步，都会按下面格式给出，绝不只说“创建一个类”：

1. **为什么做**：这一步解决什么问题，用一句大白话说明。
2. **文件放哪**：给出完整磁盘路径。
3. **怎么点**：在 IDEA 中从哪个包右键、点击什么、输入什么名字。
4. **写什么**：给出完整可运行的代码；不要求你补全省略部分。
5. **每段代码的意思**：解释关键注解、字段和方法。
6. **怎样确认完成**：运行什么或用浏览器/Apifox 请求什么，应该看到什么结果。

后端接口不使用 `@WebMvcTest`、MockMvc，也不在 `src/test` 中模拟发 HTTP 请求。所有接口都由你启动项目后，在 Postman（或 Apifox）手动测试；所有前端页面由你在浏览器中手动操作验证。可以使用 JUnit 测试不涉及 HTTP 的纯业务逻辑，例如验证码是否过期、订单状态能否从“待付款”变为“已付款”。

## 先看这里：本项目的真实目录和创建规则

你已经创建的后端项目名是 `campus-trade-server`，Spring Initializr 自动生成的根包是 `com.campus.trade.campustradeserver`。后面的所有后端 Java 文件，都从这个包开始创建；不要照着网上示例把文件建到别的包里。

```text
CampusPlatform/                                      项目总目录
├── campus-trade-server/                             后端项目
│   └── src/main/java/com/campus/trade/campustradeserver/
│       ├── CampusTradeServerApplication.java         启动类，已有
│       ├── common/                                   公共代码
│       ├── auth/                                     阶段 1：认证相关代码
│       ├── product/                                  阶段 3：商品相关代码
│       ├── favorite/                                 阶段 4：收藏相关代码
│       ├── order/                                    阶段 5：订单相关代码
│       └── admin/                                    阶段 6：管理员相关代码
├── campus-trade-web/                                阶段 0 创建的 Vue 前端项目
└── docs/学习清单/                                    你正在看的学习清单
```

在 IDEA 里创建后端文件时，统一按这个操作：

1. 在左侧找到 `src/main/java/com.campus.trade.campustradeserver`。
2. 要创建文件前，先右键这个根包，选择 `New → Package`，输入清单写出的包名，例如 `common.web`。
3. 右键刚出现的包，选择 `New → Java Class`，输入类名，例如 `HealthController`。
4. 保存后检查第一行 `package`：必须以 `package com.campus.trade.campustradeserver...;` 开头。

后续清单中的“创建 `xxx` 类”都会同时写出完整文件路径、要在 IDEA 新建的包名和类名。看见“修改”就打开已存在文件；看见“创建”才新建文件或包。

## 阶段顺序

| 阶段 | 学习目标 | 后端重点 | 前端重点 | 通过标准 |
|---|---|---|---|---|
| 0 | 初始化 | Spring Boot 骨架、统一返回、异常处理 | Vue 3 骨架、Axios、路由、代理 | 前端能调用 `/api/health` |
| 1 | 认证 | 邮箱验证码、注册、JWT 登录、退出 | 暂不接页面 | Apifox 可完成注册、登录、退出 |
| 2 | 前端登录与权限 | 获取当前用户、角色授权 | 注册/登录页、Token、路由守卫、动态菜单 | 学生不能访问管理员路由/API |
| 3 | 商品 | 分类、商品 CRUD、搜索、分页、图片校验 | 商品广场、详情、发布、我的发布 | 用户只能维护自己的在售商品 |
| 4 | 收藏 | 收藏关系、去重、分页 | 收藏按钮、我的收藏 | 无法重复收藏，数据只属于本人 |
| 5 | 订单 | 事务下单、取消、模拟付款、确认完成 | 下单与订单列表 | 一件商品不会被重复购买 |
| 6 | 管理台 | 管理员管理分类、用户、商品、订单 | 同项目动态管理员菜单与管理页 | 普通学生的管理员请求返回 403 |
| 7 | Redis | 分类、热门商品缓存与失效 | 热门商品区 | 能看到缓存命中、失效和回填 |
| 8 | 质量 | Postman 手动验收、错误码、日志、README | 加载/空/错误状态、基础适配 | 从注册到交易完成可复现 |
| 9 | 部署 | Dockerfile、Compose、环境变量 | 构建产物由 Nginx 提供 | 一条 Compose 命令后可访问 |

## 每阶段固定流程

1. 在 `docs/api/` 先写：接口地址、请求参数、响应字段、权限、错误情况。
2. 涉及数据时先写 SQL 迁移和表结构说明。
3. 启动后端后，用 Postman 保存接口请求；先写下你预期会成功或失败的结果。
4. 完成后端 Controller → Service → Mapper。
5. 用 Apifox 测试：正常、未登录、越权、参数错误。
6. 再接 Vue 页面，处理加载、空列表、请求失败。
7. 通过后提交 Git；提交信息写清做了什么。
