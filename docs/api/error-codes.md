# HTTP 状态与错误码

> 2026-09-08 按当前异常处理器、安全处理器和业务异常抛出点整理。本文是实现对照，不代表所有错误分支已完成阶段 8 实测。

## 响应格式

```json
{
  "code": 3001,
  "message": "商品不存在",
  "data": null
}
```

以上示例的 **HTTP 状态是 400**。客户端分别读取 HTTP 状态和 JSON `code`，不要把业务码 3001 当 HTTP 状态，也不要只根据 message 判断业务分支。

成功请求当前返回 HTTP 200、code=0；message 可能是 `ok` 或具体操作提示。本文不承诺所有框架错误都已统一为该 JSON 格式。

## 通用错误与鉴权

| HTTP | code | 用户可见 message | 触发条件/处理位置 |
| --- | --- | --- | --- |
| 400 | 400 | DTO 校验注解的首个字段错误；无法取得字段信息时为“请求参数不合法!” | `MethodArgumentNotValidException`；当前不返回独立 field 字段 |
| 400 | 400 | 请求参数不合法 | `MethodArgumentTypeMismatchException`，如类型转换失败 |
| 400 | 400 | 请求体不能为空或 JSON 格式不正确 | `HttpMessageNotReadableException` |
| 400 | 400 | 商品ID必须为正整数 / 订单ID必须为正整数 | Controller 或收藏 Service 的显式 ID 校验 |
| 400 | 400 | 请在60秒后再试 | 邮箱验证码发送限频，当前不是 HTTP 429 |
| 400 | 400 | 订单创建后查询失败 / 创建订单失败 / 订单号生成失败，请重试 | 订单服务的显式失败分支 |
| 401 | 401 | 未登录或 Token 无效 | 安全入口拒绝：受保护请求未认证、Token 无效/过期/已退出、用户不存在/被禁用等 |
| 403 | 403 | 权限不足 | `RestAccessDeniedHandler`；普通用户访问管理员接口、商品/订单归属不符；不直接返回 Service 内部的详细异常文案 |
| 503 | 503 | 认证服务暂时不可用，请稍后重试 | JWT 过滤器中 Redis 连接失败、查询超时或 Redis 系统异常；拒绝继续鉴权 |
| 503 | 503 | 服务暂时不可用，请稍后重试 | 控制器调用中的 Redis 连接失败、Redis 系统异常、查询超时；如验证码读取/写入、退出黑名单写入失败 |

`QueryTimeoutException` 也可能来自数据库，所以全局 503 不专指 Redis。匿名分类与热门商品已捕获缓存异常并降级查询 MySQL，Redis 故障本身不使这两条匿名请求返回 503。携带有效 Token 时仍需黑名单检查，Redis 故障会在过滤器中返回 503。

## 业务错误

以下显式 `BusinessException` 均被 `GlobalExceptionHandler` 转换为 **HTTP 400**。同一个 code 的文案可能随业务场景变化。

| code | 当前 message | 触发条件 |
| --- | --- | --- |
| 1001 | 验证码无效或过期 | 注册校验验证码失败 |
| 1002 | 用户名或邮箱已存在 | 注册前重复检查命中 |
| 1003 | 账号已禁用 | 登录或当前用户服务检查用户状态；受保护请求通常先由过滤器拒绝为 HTTP 401 |
| 1004 | 用户名或密码错误 | 登录用户不存在或密码不匹配 |
| 1005 | 用户不存在 | 管理员修改不存在用户的状态 |
| 1006 | 不能禁用当前登录管理员 | 管理员尝试禁用自己 |
| 2001 | 分类名称已存在 | 分类新增/编辑重复检查命中 |
| 2002 | 分类不存在 / 分类不存在或已停用 | 管理员操作不存在分类，或商品发布/编辑使用无效分类 |
| 3001 | 商品不存在 / 商品不存在或不可公开访问 / 商品不存在或当前状态不可收藏 / 商品不存在或不可交易 | 商品查询、管理、收藏或下单时对象不存在或状态不可用 |
| 3003 | 当前商品状态不允许此操作 / 当前商品状态不允许下架 / 当前商品状态不允许下单 | 商品状态校验或条件更新失败 |
| 3004 | 商品图片不合法 | 图片校验失败，包括编码、内容或大小等限制 |
| 4001 | 订单不存在 / 订单详情不存在 | 订单或详情不存在 |
| 4002 | 当前订单状态不允许取消 / 当前订单状态不允许付款 / 当前订单状态不允许确认完成 / 订单关联商品状态异常，取消失败 / 订单关联商品状态异常，付款失败 | 订单状态或关联商品状态冲突 |
| 4003 | 不能购买自己的商品 | 买家等于商品卖家 |
| 401 | 用户不存在或登录已失效 | `AuthService.getCurrentUser` 查询不到用户的业务异常；此分支实际为 **HTTP 400、code=401**，与安全入口的 HTTP 401 不同 |

## 已知边界与后续验收

- 正常路径中 JWT 过滤器已检查用户，但过滤器与 Service 查询之间仍可能发生状态变化。上述 HTTP 400/code=401 是实现边界，不应在文档中直接写成 HTTP 401；统一行为属于后续代码整改。
- 未知路径、方法不支持、`HandlerMethodValidationException`（例如方法参数上的 `@Positive`）等未在当前全局处理器中逐类统一；框架最终返回格式与错误分派需实测，不预先承诺统一业务码。
- 注册与分类的预查询重复检查会返回 1002/2001，但不代表并发时数据库唯一键异常都已转换。收藏 Service 单独捕获重复键并按幂等成功处理。
- 当前没有通用未知异常处理器，不能声称所有异常均无堆栈或敏感信息泄露；阶段 8 需继续检查实际响应和日志。
- 参数提示目前取首个错误，尚无统一字段列表；日志请求 ID 和验证码日志整改也尚未完成。
- 本文不修改健康检查权限或禁用用户重新启用后的 Token 行为，参见 [手动验收差异表](../manual-acceptance.md)。
